# 給 SOL 6.1：縮短說出需求到完成工作的流程

這是一份待實作工作單。適用基準為 QA agent 1.0.0rc5，整理日期為 2026-10-27。使用者已確認 App 可以運作，本輪優先改善「說出需求到完成工作，步驟太多」。本文件完成不代表介面已改版或人工使用性已驗收。

## 直接交給 SOL 6.1 的指令

> 請依 docs/UX-SIMPLIFICATION.md 實作工作流程精簡。先讀 AGENTS.md 的最新規則與 .github/copilot-instructions.md，檢查現場分支及未提交修改，再追蹤目前主對話到工作成果的路徑。沿用已正常的環境、達哥接線與資料，不重新跑整套啟用或重裝套件。先用隔離的合成資料走一遍既有操作，記下必須點擊、切頁及重填的地方，再分段修改。目標是一個輸入框、一張工作卡，使用者補齊必要條件並確認一次後，在原處看到成果。保留真正的執行批准、排程持續同意、來源核對及請求恢復限制。不要只交計畫或做配色，也不要新增框架、功能頁或另一套執行服務。依第 6 節完成驗證，交付實際畫面、操作前後差異和未測項目。真實服務測試另需明確授權，不因本工作單自行消耗 API。

本工作單是本次任務入口。[TO-AGENT](../TO-AGENT.md) 的完整安裝與接線流程只在有實際環境或連線阻塞時使用。安全與開發共用規則以 [Copilot 指引](../.github/copilot-instructions.md) 為準，不再建立一份重複接手文件。

## 1. 先核對已經完成的部分

以下是目前程式可確認的行為，不是本輪新增目標。現場分支可能已有修改，先核對再動手。

- 主側欄已收斂為「對話、我的工作」，不要再設計新的主導覽。
- [WorkspaceTurns](../desktop_app/workspace_turns.py) 已讓普通對話、工作建議與工作補充共用入口。
- [workspace-ui.js](../desktop_app/web_assets/workspace-ui.js) 已把補問放回原對話輸入框。
- [agent-jobs.js](../desktop_app/web_assets/agent-jobs.js) 的 inline 路徑已有自動本機預覽，並移除額外的預覽按鈕。不要把這件事當成尚未完成而重寫。
- [AgentJobs](../desktop_app/agent_jobs.py) 已提供 preview、confirm、inspect、recover、schedule。沿用這些服務，WorkflowService 與 LangGraph 繼續負責執行。

先走查下列可能增加負擔的地方。這些是靜態閱讀發現的改善候選，不是已證實的故障或點擊次數測量。

| 目前程式位置 | 需要實際核對的問題 | 本輪處理方向 |
|---|---|---|
| `agent-jobs.js` 的 `show`、`renderPlan` | 工作標頭、步驟卡與批准卡分別呈現需求和說明。即使在同頁，使用者仍須來回閱讀。 | 合成一張工作卡，將重複說明合併，讓批准範圍可一次核對。 |
| `renderPlan`、`editPlan` | 預設內容包含步驟 ID、前置輸入、模型額度；修改視窗要求填逗號分隔的前置 ID。 | 以自然語言補充作為主要修改方式，技術編輯留在進階細節。 |
| `renderResult` | 成果後同時提供複製、完整紀錄、存 Skill、記憶及排程。 | 先讓人閱讀成果，次要保存操作收進「更多」。 |
| `workspace-ui.js` 與 `WorkspaceTurns.choose` | 模糊需求選「直接回答」後，目前只填入新草稿，仍須再送出。 | 評估合併為一次明確的送出操作，見第 4 節。 |
| `app.js` 的 `renderMyWork` | 多種狀態主要都用「查看工作」。 | 依真實狀態顯示可理解的下一步，但先開啟內容，不直接批准。 |

不要刪除進階能力或歷史。收合的是日常不需要的控制項，資料與服務保留。

## 2. 先完成這條使用旅程

使用一位已可用的助理。進入 App 後直接看到輸入框，不必先選 Plan、角色、Skill 或開啟管理頁。

1. 使用者輸入「每天早上八點，幫我整理台股、美股和重大總經新聞，附上來源」。
2. App 在原對話準備工作。缺條件時只問必要問題，已提供的市場與時間不重問。條件不足仍須補問，不能為減少步驟而猜答案。
3. 條件完整後呈現一張「這次先試跑」工作卡。使用者可直接補充需求，也可按「確認執行」。此時還沒有啟用每日排程。
4. 執行後在同一卡片顯示進度，再換成完整成果。無須切到活動紀錄或再按「查看完整成果」才看到正文。
5. 使用者核對成果及來源後，可按「設為自動工作」。同一處完成時間檢查、成果核對與持續傳送同意，再按「確認啟用」。
6. 啟用後顯示下次台北時間、暫停入口，以及 App 必須開啟或留在系統匣的限制。原成果仍可閱讀。

這裡的「確認一次」只指一次工作執行。每日排程是另外的持續授權，不能跟第一次執行合併或自動勾選。

純文字需求，例如「把這段工作筆記整理成重點」，沿既有普通對話直接回答。不要為所有問答增加工作卡或批准。

## 3. 將工作卡改成一個持續更新的區塊

### 一次只突出下一個主要操作

依服務回傳狀態呈現下表。表中是顯示規則，不是新的持久化狀態機。取消、關閉及資料來源入口不能因只有一個主要按鈕而消失。

| 當下情況 | 預設看得到的內容 | 主要操作 |
|---|---|---|
| 正在準備計畫 | 使用者需求、目前助理、正在準備提示 | 可停止；不顯示可執行的批准按鈕 |
| 缺少條件 | 必要問題、可選答案、已填條件 | 「送出補充」 |
| 等待批准 | 工作目標、短步驟、目的助理、資料與工具範圍、執行上限、尚未執行 | 「確認執行」 |
| 已排隊或執行中 | 目前真實狀態、可讀的已完成步驟 | 「停止工作」，停止後顯示取消中直至真實請求收尾 |
| 已完成 | 成果全文、資料時間與來源限制 | 「複製成果」；自動工作是另一個明確的後續入口 |
| 已失敗或未完成 | 安全錯誤說明、已取得內容、是否已送出 | 由既有恢復能力決定的「檢查原請求」或「取回結果」 |
| 已取消 | 已取消狀態與已取得內容 | 查看原有內容，不自動重試 |

收到 AI 文字不等於成功，也不等於事實已核實。`needs_input`、額度耗盡、來源不足與遠端失敗沿既有狀態處理，不為呈現綠色卡片改寫結果。

### 縮短閱讀量，保留批准所需資訊

預設展開目標、建議步驟，以及會傳給誰、哪些資料、可用哪些搜尋工具與額度上限。這些是批准依據，不能全部藏到「詳細資料」才看得到。

將修訂號、request ID、內部步驟 ID、前置依賴與完整執行紀錄移到「詳細資料」。長篇 Skill 或記憶內容可展開閱讀，但預設仍列出選入的項目與傳送範圍。不得默默選入、截斷或改寫批准快照。

避免同時顯示重複的「工作與成果」「工作目標」「計畫步驟」「確認後開始這份工作」大型區塊。保留一個主標題和必要分段即可。

簡化後的待確認卡可依這個文字配置實作，實際內容必須來自已驗證的預覽資料。

```text
財經日報                                  等待你確認
這次先試跑，尚未啟用每天執行。

由「市場助理」整理台股、美股與重大總經新聞。
將傳送本次需求和明確選入的資料，僅使用列出的核准搜尋工具。

建議做法
1. 搜尋指定範圍並保留來源
2. 整理重點及尚待核對的資訊

工具：依預覽列出核准工具
上限：依預覽列出動作、模型請求及時間上限

[修改需求] [詳細資料]              [確認執行]
```

### 修改回到同一個輸入框

按「修改需求」時聚焦目前輸入框，明示「補充目前工作」。不要再開一份相同需求表單。選項與文字一併送出，保留尚未送出的內容，送出成功後才清除。

使用者有未提交修改時，舊批准按鈕保持不可用，旁邊說明「先送出修改，再確認執行」。送出後沿現有修訂與預覽失效規則產生新卡片。

步驟排序、依賴 ID 與額度編輯保留在進階入口。這輪先不另外開發視覺流程編輯器。

### 成果可直接閱讀

完整成果保留文字選取、來源與資料時間。執行紀錄預設收合。長文先使用工作區主捲動，不要求使用者在多層狹窄文字框中反覆捲動；1050×700 下仍須能到達操作列。

「存為 Skill」「記住偏好」「完整紀錄」放入成果旁的「更多」。保留原本的預覽及保存規則，不因移動入口直接保存。

資料來源缺失時明示缺失。介面不得額外呼叫模型來補摘要、標題、來源或編造一份好看的成果卡。

## 4. 把兩個次要中斷點接回同一流程

### 模糊需求不要要求同一意圖點兩次

目前「直接回答」只是填稿。可以改為「直接回答並送出」，在按鈕旁先展示實際會送出的補充文字。一次點擊才送出，這是使用者主動發送的一則新訊息。

只對已完成、仍有效的 clarify 建議提供此操作。若輸入框已有其他草稿，先保留草稿並讓使用者決定是否使用建議，不覆蓋或暗中送出。沿用對話服務的請求識別、狀態及背景請求檢查，不重送任何未知結果的舊請求。載入頁面、切換對話或重新整理都不能觸發發送。

若現場服務不能在保留上述條件下合併，先完成工作卡精簡，將此項列為未完成。不要靠前端盲目串兩次呼叫來假裝解決。

### 回到工作時，按鈕說清楚會看到什麼

在「我的工作」將一般的「查看工作」依既有狀態改為「補充條件」「查看待確認計畫」「查看進度」「查看成果」或「處理中斷」。點擊後開啟同一來源工作卡，不另建立任務，也不代替使用者批准。

保留現有優先待處理排序、狀態篩選及工作去重。不要新增儀表板、另一份待處理清單或第二套完成狀態。

自動工作時間若已有經驗證的結構化值，才帶入表單。只有自然語言文字時，保留原需求讓使用者核對並填一次時間。既有 `08:00` 預設須標為建議值，不能呈現為已正確理解使用者的排程。這輪不為自動填時間擴充模型契約或增加解析請求。

## 5. 依這個順序修改

### 第一段，核對現況並縮小主流程

先用合成資料走一般問答、完整工作需求、缺條件工作三條路徑。記下送出、切頁、重填、開彈窗及看見完整成果的操作。不要只統計按鈕數，也記錄批准範圍是否容易找到。

將前後對照寫進現有 [驗證紀錄](VALIDATION.md) 的精簡摘要。原始測試與截圖使用忽略的 `artifacts` 目錄，不新增逐版規格包。只讀程式或舊截圖不能標成人工驗收。

### 第二段，先改同頁工作卡，再改次要入口

| 修改範圍 | 優先入口 | 保留的邊界 |
|---|---|---|
| 卡片、補問、批准、進度與成果 | [agent-jobs.js](../desktop_app/web_assets/agent-jobs.js) 的 `show`、`renderPlan`、`renderResult` | 同一份 `AgentJobs.state`；不新增結果快取或成功狀態。 |
| 主輸入框與工作目標 | [workspace-ui.js](../desktop_app/web_assets/workspace-ui.js)、[dialogue.js](../desktop_app/web_assets/dialogue.js) | 草稿、游標、選取、來源對話及待補充工作不能串線。 |
| 版面與可見性 | [index.html](../desktop_app/web_assets/index.html)、[app.css](../desktop_app/web_assets/app.css) | 保留深淺主題與語意色，文字與圖示共同表示狀態。 |
| 工作清單與更多操作 | [app.js](../desktop_app/web_assets/app.js) 的 `renderMyWork` | 不重做導覽、排程器、刪除或資料生命週期。 |
| 模糊需求的一次明確發送 | [workspace_turns.py](../desktop_app/workspace_turns.py) 的 `choose` 與既有對話送出路徑 | 只有必要時才改服務；Web 與 CLI 契約保持一致。 |
| 批准、恢復與排程 | [agent_jobs.py](../desktop_app/agent_jobs.py)、[workflows.py](../desktop_app/workflows.py) | 預設不改；若 UI 需要新能力，先指出現有介面缺口與最小修改。 |

每完成一段就驗證相關旅程。不要一口氣重寫 `app.js`、資料庫或達哥連接器。使用既有 Python 3.10.4、WebView、Tk 備用及 69 wheels，不新增套件、資料庫 schema 或背景模型請求。

### 第三段，保留會影響使用者的狀態

更新既有控制項時保留草稿、未送出選項、閱讀位置及文字選取。切換對話、主題、檢視細節與輪詢進度都不能重建工作或抹掉編輯。

待批准卡的主要操作在小視窗可到達，且不遮住輸入框。可用卡片內黏附操作列，但不要強制使用者捲到底才算同意，或用固定浮層蓋住來源與取消。

聊天可用而工作能力未通過時，保留聊天，在工作卡提供缺少項目的設定入口。不要要求使用者重跑已通過的全部啟用測試。未知送出仍只提供既有允許的檢查與恢復，不新增一個通用「重試」按鈕。

## 6. 按使用旅程驗收

| 旅程 | 必須看得到的結果 |
|---|---|
| 一般問答 | 輸入後直接回答，沒有新增批准或額外意圖分類請求。 |
| 已驗證助理、條件完整的工作 | 送出需求後原處出現待批准卡；按一次確認執行，原處看到完整成果。不要再要求開管理頁或點預覽。 |
| 缺條件與修改 | 只補缺項；已填值保留。送出修改使舊批准失效，選項不代替授權。 |
| 執行與切換 | 雙擊不多派發；切換主題、對話及返回後仍是同一工作，草稿和選取未遺失。 |
| 成果與自動工作 | 成果可閱讀及複製；排程先試跑成功、人工核對再另行同意，不自動開啟。 |
| 失敗與未知送出 | 原對話與部分成果保留；恢復操作只來自服務允許的能力，不以新 request ID 重送。 |
| 重新開啟 | 找到原工作與待確認內容，只恢復畫面，不自動派發或批准。 |
| 小視窗與鍵盤 | 真 WebView 深淺主題及 1050×700 下，補充、確認、停止、來源和關閉可達。Enter、Shift+Enter 與既有 IME 保護保留。 |

合成介面旅程不能驗收真實搜尋品質。示範模式不得開啟真實排程，也不能為了測試這條路徑放寬服務限制；排程授權用現有隔離測試資料驗證，現場另行核對。

選測命令沿用現有入口，按實際修改範圍選擇，不必每輪全部重跑。

```powershell
.\.venv\Scripts\python.exe scripts/test_runner.py --suite targeted --tests tests.test_workspace_turns tests.test_agent_jobs tests.test_web
.\.venv\Scripts\python.exe scripts/web-smoke.py --workspace-only
```

只修改樣式或文案時，選相關畫面及測試。改動發送、補充或工作操作時，加跑一次 quick。改核心服務或準備正式交付時，用 `scripts/verify.py development` 完成一次完整驗證，不先跑 full 再重複 verify。測試入口與選項以 [開發指南](DEVELOPMENT.md) 及現場 `--help` 為準。優先擴充既有行為案例，不為每個文案或按鈕另建測試。

交付時請一位未看手冊的使用者，從空白對話完成一件工作。記下他停在哪裡、是否理解即將傳送的內容，以及能否自行找回成果。沒有人可試用就標 `manual_usability=not_tested`，不要把自動點擊成功稱為已證明直觀好用。

## 7. 提交可核對的結果

完成後交付一份短摘要，說明刪減了哪些操作、仍保留哪些必要確認，以及前後實測差異。若原流程本來只有兩次主要操作，就如實報告沒有減少次數，改以閱讀量、切頁和重填改善說明，不造速度數字。

更新 [使用手冊](USER-GUIDE.md)、[驗證紀錄](VALIDATION.md) 與 manifest。精選截圖替換現有介面圖，不累積歷代材料。回報測試命令、完成退出碼、未通過項目和現場未測限制。保留候選版標示，不因 UI 改完就宣稱正式 1.0 或完整 Hermes。

若出現已可重現的功能缺陷，與版面偏好分開記錄，先修會阻擋主旅程的項目。拿不準的內部契約用去識別問題確認，不索取 API key、完整 SQLite 或原始 HTTP。
