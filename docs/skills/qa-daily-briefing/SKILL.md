# 每日搜尋交辦

在 QA agent 專案目錄工作；先讀 `docs/WORKBENCH.md`。不重新安裝正常環境，不讀取或顯示 keyring 金鑰、`.env`、HTTP body。

1.0.0rc2的新交辦優先使用 [工作代理](../../AGENT-WORK.md) 中的 `/job-create`、`/job-preview`、`/job-run`、`/job-schedule`。一般 `/job` 預設純文字；搜尋工作用 `/job-create` 明確指定 `search:true`，只能選已驗證主助理與核准工具。不必先建立Skill。必要補問依實際 `questions` 回答；有限補查最多2輪、12模型請求、600秒，不能自行提高或改用別的工具。`needs_input`／超限時保留部分成果請人核對。由使用者互動確認執行，成功後另核對來源及持續傳送，不能由本Skill代填批准。`/job-skill`只產生可編輯草稿，不自動保存。下方 `/order` 只用於原有每日交辦，不能拿其ID操作新job。

1. 確認桌面已退出：CLI 與桌面（含系統匣）共用工作區鎖。不要繞過鎖或另開副本假裝資料同步。
2. `qa.bat assistants` 列出可用的本機 profile ID。一般聊天的 `company:...` 識別與工作 profile ID 不可互換。搜尋核准只是授權，不代表來源品質已驗收。
3. 使用者只想展示時，改用 `qa.bat --demo`。此模式不讀正式設定，關閉後清除暫存資料；不能建立真實排程。
4. 互動工作台中 `/order <profile ID> <需求>` 只建立交辦並呼叫工具停用的規劃回覆。檢查缺少的新聞範圍、允許來源與每日台北時間，請使用者補充，不自行猜測。
5. `/order-edit {"scope":"台股＋美股＋重大總經新聞","sources":"公開網路可靠來源","time_hhmm":"08:00"}` 保存明確條件。`/order-preview` 不執行搜尋。
6. 將預覽交給使用者。由使用者在互動終端執行 `/order-run` 並確認試跑，或關閉 CLI 從桌面交辦紀錄確認。不得自己輸入批准字串、以 PTY 假裝人類，或修改服務授權旗標。
7. 用 `qa.bat orders` 或工作台 `/orders` 查看狀態；`/result <task ID>` 取成果。核對日期、來源及範圍；來源缺失就明示，不補造引用。
8. 人工核對後，由使用者 `/order-enable` 明確同意每日持續傳送。CLI 不運作排程，退出後開桌面並保持視窗／系統匣程序運作。關機、睡眠或登入到期不能保證準時執行。

失敗時先 `/order-inspect`。只有可恢復的已知規劃請求才使用 `/order-recover`，仍沿原識別，不新建請求冒充恢復。日報試跑失敗不能自動重跑；保留原結果與原因。改條件或連線後需新交辦、新試跑及新確認。

交付回報列出工作ID、本機執行狀態、是否人工核對、排程啟停與下次時間；收到模型文字不能回報為「事實已驗證」。這份 Skill 不擴大使用者授權，也不啟用未核准工具。
