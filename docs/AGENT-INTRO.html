先不要介紹名詞。請同事想想，上次準備週報時，是寫字花時間，還是找齊資料、確認誰說的才花時間？今天沒有介紹任何待發布產品，也沒有即時讀取信箱。

02 / 16 · 停下來問同事

你最常卡在哪一段？

先選一個最有感的，不需要提供任何真實信件。

A 找

「那封信在哪？」

記得有人提過，卻忘了主旨、時間與附件版本。

B 確認

「後來有改嗎？」

舊報告與新信件不同，還要回頭追問。

C 整理

「又要重做一次。」

每週都要分類、排版，再列出待辦與待決策事項。

大家想過後，再揭示這頁的重點

只會寫摘要還不夠。我們需要的是把「找、確認、整理」接成可追查的工作。

給同事約十五秒舉手或回應。只選一兩個回答，不收集私人資料。這個問題沒有標準答案，也不把現場反應轉成績效統計。

03 / 16 · 同一件工作，換一種分工

哪些步驟可以交出去？

原本主要靠人
  1. 找出本週相關信件
  2. 比對上次紀錄與舊簡報
  3. 確認矛盾、追問缺項
  4. 重寫摘要、待辦與投影片
具備工具的 AGENT 可協助
  1. 在指定範圍找資料並保留來源
  2. 整理差異，標出不一致之處
  3. 能補查就補查，仍未知就詢問
  4. 按核准方法產生可修改草稿

人決定目標、權限與採用；Agent 協助推進中間的操作。

聊天由人逐步引導；固定自動化依預寫規則；Agent 可依結果選擇下一步。三者可以搭配。

不是宣稱人會完全退出。聊天也能摘要，程式也能寫分支；代理的特點是模型可以在允許動作內依結果決定下一步。不比較未量測的工時，也不把所有工作都包裝成需要代理。

04 / 16 · 選題比選名詞重要

先挑值得試，也容易核對的工作。

適合先試

範圍小、來源清楚、成果可改

  • 整理指定主題的信件摘要
  • 從會議紀錄列出已有依據的待辦
  • 把已確認資料轉成週報草稿
先補條件，再談自動化

資料不明、影響大、難以回復

  • 「自己找所有重要資料」但沒定範圍
  • 直接承諾期限、價格或責任
  • 未核准就寄出、覆寫正式紀錄
四個判斷：來源明確嗎？常重複嗎？能核對嗎？出錯後能修正嗎？
這不是禁止清單，而是選擇第一個試點的方法。偶爾一次且很簡單的工作，直接聊天可能比較省事；高影響動作要先設清楚權限、確認與回復方法。

05 / 16 · 使用前須知

開始前，先確認這四件事。

資料

哪些內容能提供？

指定主題、期間與來源。使用組織核准服務，不把整個信箱當成預設範圍。

能力

工具真的接好了嗎？

讀信、查紀錄、建立 PPT 各有接線需求；收到文字不等於已做實際操作。

保存

哪些會留下來？

了解對話、記憶與產出存在哪裡，以及如何修改、停用或刪除。

責任

做到哪裡要停？

誰核對、成果交到哪裡、遇到未知如何處理，都先說清楚。

沒接信箱的工具，仍可由人貼入核准可提供的資料來整理。這不是失敗，是另一種使用方式。不要以「請讀信」或「請記住」這幾個字，推定權限和保存都已完成。

先讓同事看見一張能看懂的計畫。不是每句普通聊天都要批准，也不是切到某個模式就保證安全。不同平台控制方式不同，重點是執行前知道它要取哪些資料、做哪些動作。

07 / 16 · 目標、來源、成果、限制

可以直接套用的交辦方式。

目標：讓與會者了解本週進度與待決策事項。

來源：只使用我指定的本週信件與上次會議紀錄；保留來源名稱。

成果：先給摘要與待辦表，再整理五頁簡報草稿。使用繁體中文，先結論、後依據。

限制：先列計畫與必要問題，等我確認再做。不要補造負責人或期限，不寄出、不改原始資料。

不用背提示詞術語，把同事交接工作時需要知道的事講清楚。

這份提示可以調整成自己的工作，但不能讓沒有讀信工具的聊天介面突然擁有信箱權限。先說明它實際可取得的資料。平台若只能文字輸出，請它先交出簡報內容大綱。

08 / 16 · 預先編寫的案例，不是即時 AI

遇到新資訊，就重新判斷下一步。

較新的信件，不一定就是已核准的結論。

1／讀取指定範圍

信件 B：「交付提議改到週五，待確認。」
信件 C：「表單校對完成；作業說明初稿待確認。」

來源僅限指定信件。沒有讀取整個信箱。

2／檢索上次紀錄

會議紀錄 A：「交付原訂週三完成。」

取回原文與來源，不把記憶中的日期當作最新事實。

3／發現需要處理的矛盾

A 是週三，B 提議週五但尚未確認。

Agent 可以在核准範圍補查；沒有證據時，不自行選一個日期。

4／問一個影響成果的問題

Agent：「週五已核准嗎？」
使用者：「還沒，請標成待決策。」

這是虛構回答，不會發送訊息或呼叫模型。

5／保留未知，交出草稿

「交付期限待確認：原訂週三，後續提議週五。」

來源：A、B、使用者補充。下一頁展示摘要、待辦表與五頁大綱。

選動作 → 用工具 → 看結果 → 繼續、詢問或停止。次數、時間、成本與權限都要有界線。

逐步點選，而不是一次念完五步。請同事先猜：會直接寫週五，還是保留待確認？這是模型依回饋選擇下一步的示例。實際系統也可能判斷錯誤，所以要保留來源與核對入口。

09 / 16 · 虛構輸出，與前頁來源一致

不是一句「完成」，而是三份可核對的成果。

信件摘要

表單校對完成；作業說明初稿待確認。[C]

交付期限原訂週三，後續提議週五，尚未核准。[A、B、使用者補充]

五頁簡報草稿大綱
  1. 摘要：校對完成，兩項待確認
  2. 已完成：表單校對 [C]
  3. 進行中：作業說明初稿待確認 [C]
  4. 待決策：交付期限 [A、B]
  5. 來源：A、B、C 與使用者補充
待辦表 · 未提供的人與時間，維持未知
事項依據狀態負責人／期限
確認作業說明初稿信件 C待確認未提供／未提供
確認交付日期A、B、使用者補充待決策未提供／待確認

這裡展示內容草稿；建立真正 PPT 檔需簡報工具。沒有自動寄出或改寫來源。

讓大家看一次內容對照：校對確實完成，初稿不等於正式完成，週五也不是已核准期限。附來源不保證內容正確，但讓人更容易回頭核對。

10 / 16 · 記憶減少重複交代

下週不用重講習慣，但進度仍要重新查。

第一次

說清楚，再確認保存

「繁體中文、先結論、附來源；週報用摘要／進度／待決策。」

在支援的平台，檢查哪些偏好已保存，以及能否修改或刪除。

下週

沿用格式，更新事實

「用已確認的格式整理本週資料。重新查進度，不沿用舊期限。」

系統按設定讀取記憶或檢索紀錄；未支援時，由人提供格式。

本次對話這次要五頁
＋
已保存偏好先結論、附來源
＋
重新查核本週信件與進度

「請記住」不代表永久保存成功。記憶會過期或遺漏；保存不是訓練模型。

Hermes 只是參考之一，各平台讀取記憶的時機不同。保存的是偏好或筆記，不是讓模型天然記住所有公司資料。不要因為舊紀錄寫週三，就跳過本週信件。

11 / 16 · 回到剛才的週報

工具、Skill、分工：各自解決不同問題。

工具

可以操作什麼？

讀指定信件、查會議紀錄、產生簡報檔。

需要實際接線與權限。

SKILL 工作方法

照什麼方法做？

先比對前後差異，再列摘要、進度與待決策。

方法可重用，不能憑空增加權限。

多代理

要不要分工？

一位整理，另一位對照來源檢查。

需要協調，仍可能一起犯錯。

先讓一位代理完成一件工作。有需要再保存方法或增加分工。

不要讓聽眾以為必須先建一堆 Skill 或四位助理才能使用。單次工作可以直接交辦。不同平台的 Skill 結構不同，這裡用工作方法說明用途，不提供腳本或安裝指令。

12 / 16 · 比漂亮更重要的三項核對

試跑後，先看它有沒有做對。

來源與內容

能對回原文嗎？

表單完成有信件 C；週五仍是提議，沒有被改成承諾。

未知與缺項

有沒有偷偷補造？

負責人、期限與未取得資料要明示，不能為了填滿表格猜答案。

成果與用途

真的能接著用嗎？

能修改、有來源、符合會議需要；重要內容經人核對。

先修正一次工作的做法，再把它變成每週自動工作。

評估時間要包含人工檢查與修正，不只看生成速度。

如果每次草稿都要大修，就先改善來源、範圍或方法，不要急著排程。模型說完成、工具成功回傳與成果值得採用，是不同層次。
