# Agentic AI：給產圖 agent 的八頁簡報製作指令

用途：向非技術同事介紹 Agentic AI，再以 QA agent 說明實際工作方式。預計講述 10 分鐘。本文件是製作簡報圖片的完整委託書，不是 App 設定或執行指令。

**使用方式：將整份文件交給產圖 agent。**「固定上圖文字」放進圖片；「講者補充」不上圖，可另存為備忘稿。每頁提示可獨立使用，但必須同時附上以下共用製作規則。不要只依頁面標題自由發揮。

## 給產圖 agent 的總指令

請依本文件製作八張一致風格的繁體中文簡報圖片，依序介紹「工作痛點、概念差異、運作方式、日常例子、處理流程、QA agent、人的責任、試行方向」。受眾不需要懂程式。保留固定文案的意思與未知資訊，不新增能力、成果數字或公司政策。

- 每頁 16:9，建議 1920×1080。輸出 `01.png` 至 `08.png`，另提供一張八頁縮圖索引；有能力時再附可編輯版本，不冒稱已提供。
- 配色：霧白底 `#F5F7FA`、深藍標題 `#17324D`、青綠重點 `#087F8C`、深灰正文 `#334155`。待確認用琥珀 `#B86A00`，紅色只用於錯誤。顏色必須搭配文字或圖示。
- 使用清楚的繁體中文無襯線字體；標題約 64 px、正文約 36 px、頁腳至少 24 px。四周保留約 96 px，勿為塞字而縮小正文。
- 每頁一個主要訊息、一張主圖，最多四組主要說明。統一線條圖示與圓角卡片，不使用機器人盔甲、霓虹、粒子或複雜電路背景。
- 以文件、對話、放大鏡、清單、時鐘、確認勾等圖示表意；每個圖示搭配文字。不加入虛構商標、公司識別、人物姓名或敏感資料。
- 全部頁面右下角顯示頁碼。流程圖頁標示「流程示意」；案例頁標示「虛構案例，非實際工作資料」。頁腳不是第五個主要論點。
- 箭頭要表達正確順序。回圈必須有「完成／詢問／停止」出口，不畫成無限制自動執行。
- 固定上圖文字不得改成誇大宣稱。不增加節省百分比、績效統計、引用數字、保證正確或「已全面上線」字樣。
- 中文若無法可靠產生，請交付無文字圖稿與對應文字配置表，供排版合成；不要以亂碼或錯字成品交差。
- 不需要讀取本機檔案、連線公司系統或呼叫工具展示能力。依本文件提供的虛構材料繪製即可。

## 第 1 頁：AI 可以幫我們做到哪一步？

**目的：**先讓同事認出每天的工作，不從專有名詞開始。

**固定上圖文字：**

- 標題：AI 可以幫我們做到哪一步？
- 副標：從回答問題，到協助完成一件工作
- 流程：收集資訊 → 整理重點 → 確認缺項 → 交付成果
- 重點句：我們想減少反覆整理，把時間留給判斷。

**構圖提示：**左側是三張簡單筆記，中央是整理中的文件，右側是人查看成果。四個流程節點橫向排列；最右側保留人的確認符號。用青綠標示整理流程，人的確認以深藍呈現。

**圖示含義：**筆記代表零散資訊；文件代表整理成果；人與勾代表人工核對。

**禁止添加：**不要畫 AI 自動批准業務，也不要增加效率數字。

**講者補充（不上圖，45 秒）：**我們常把時間花在找資訊、重新排版、追問缺項。今天介紹的是 AI 如何協助走完這段流程，而不是只比較誰回答得好聽。是否值得導入，要看實際工作能否做完、結果能否核對。

## 第 2 頁：聊天、自動化、代理有什麼差別？

**目的：**以同一份工作報告比較三種方式，避免把所有 AI 都叫代理。

**固定上圖文字：**

- 標題：聊天、自動化、代理有什麼差別？
- 聊天：你問一步，AI 回答一步。
- 固定自動化：依事先寫好的規則往下做。
- 代理：依目前結果，選擇下一個允許的動作。
- 重點句：三種方式可以搭配，不是越自主越好。

**構圖提示：**三欄同寬，都從「整理今日工作報告」出發。聊天欄畫交替對話；固定自動化欄畫單一路徑；代理欄畫「資訊足夠？」分支，通往整理或詢問。分支只用小標「足夠／不足」，不增加長段落。底部放重點句。

**圖示含義：**對話泡泡是問答；直線流程是固定規則；分支是依結果選擇動作。

**禁止添加：**不把排程等同自主，不把代理畫成必須由多個模型組成，不暗示固定流程沒有價值。

**講者補充（不上圖，90 秒）：**單純改寫一封信，用聊天就可能足夠。每天固定時間執行同一程序，可能只是排程。這份報告用「根據結果選擇下一步」說明代理特性：例如資料不夠時詢問，足夠時整理。固定程式也能設計分支，差別在於下一步主要由預先規則決定，還是由模型在允許範圍內判斷；不必為簡單工作增加成本。

## 第 3 頁：Agentic AI 怎麼工作？

**目的：**讓觀眾看懂計畫、工具、回饋與停止的關係。

**固定上圖文字：**

- 標題：Agentic AI 怎麼工作？
- 主流程：理解目標 → 提出計畫 → 使用核准工具 → 檢查結果
- 分支：足夠就完成；不足則補查或詢問。
- 邊界：超出權限或額度，就停止並交回人處理。

**構圖提示：**四節點圍成開放回圈。「提出計畫」到「使用核准工具」之間加明顯的「人確認」關卡。檢查結果後分流到成果、範圍內補查、詢問人；用邊界框表示可操作範圍。頁腳標示「流程示意；此處採 QA agent 的確認方式」。

**圖示含義：**靶心是目標；清單是計畫；放大鏡是核准搜尋；檢查符號表示檢查輸出，不代表真相保證。

**禁止添加：**不要畫無限循環、任意電腦操作、寄信或自動取得所有資料。

**講者補充（不上圖，90 秒）：**模型不是得到一句需求就擁有全部權限。系統要限制能用的工具、資料範圍與執行次數。工具回來的結果會影響下一步，但仍可能錯誤；重要結果要核對。人確認這道關卡是本產品的設計，並非所有 Agentic AI 系統都採完全相同流程。

## 第 4 頁：用每日工作報告來看

**目的：**提供可一路追蹤的簡單輸入，不使用真實公司資料。

**固定上圖文字：**

- 標題：用每日工作報告來看
- 筆記 A：表單校對完成。
- 筆記 B：作業說明初稿完成，尚待確認。
- 筆記 C：異常紀錄待補處理期限。
- 需求：整理成「已完成、進行中、待確認」。

**構圖提示：**左側三張筆記卡，右側一個尚空白的三區報告。C 的「期限」用琥珀底線，箭頭指向右側待確認區。頁腳必須寫「虛構案例，非實際工作資料」。

**圖示含義：**勾為已完成；文件筆為初稿；問號為缺少期限。缺資料不是系統故障，不用紅色。

**禁止添加：**不得補上日期、姓名、數量、原因、客戶或部門。B 只完成初稿，不得畫成整項作業完成。

**講者補充（不上圖，75 秒）：**這三則資訊很常見，但完成程度不同。AI 可以整理文字，卻不能把「初稿完成」擴大成「工作完成」，也不能自行指定異常處理期限。這頁是練習材料，不是已接通內部資料庫的證據。

## 第 5 頁：從筆記到可核對的報告

**目的：**展示補問與人工確認如何避免把缺項包裝成答案。

**固定上圖文字：**

- 標題：從筆記到可核對的報告
- 補問：異常紀錄的處理期限已確定嗎？
- 回答：尚未確認，請保留「待確認」。
- 計畫：依三個分類整理，不補造期限。〔確認執行〕
- 成果：已完成：表單校對／進行中：作業說明待確認／待確認：異常處理期限

**構圖提示：**四組卡片按補問、回答、計畫、成果排列。成果卡最大，三分類分行。計畫卡畫確認按鈕但標示為流程示意；成果旁以小圖示表達人工核對。頁腳標示虛構案例。

**圖示含義：**問號代表缺項；確認按鈕代表授權當下計畫；成果的問號保留未知資訊。

**禁止添加：**不加「已查詢資料庫」或「已寄出報告」，不把單次整理描述為多代理覆核。

**講者補充（不上圖，100 秒）：**先前的筆記 C 沒有期限，所以正確成果仍保留未知。這種簡單整理本身也能用聊天完成；當工作進一步需要核准搜尋、依結果補查、反覆執行與保存成果時，代理工作流程才更有價值。圖中的步驟是說明方法，不表示每個普通問答都必須經過批准。

## 第 6 頁：QA agent 如何接住這件事？

**目的：**把抽象概念連到工作區，但不宣稱候選版已完成現場驗收。

**固定上圖文字：**

- 標題：QA agent 如何接住這件事？
- 對話：說明需求，補齊條件。
- Plan：查看、修改，確認後執行。
- 成果：查看內容、來源與待確認事項。
- 重複工作：可選 Skill 保存方法；試跑核對後另行啟用排程。
- 頁腳：目前為候選版；實際助理與搜尋能力須現場驗證。排程需 App 保持運作。

**構圖提示：**畫概念工作區，中央只有「對話 → 計畫 → 成果」三階段；底部側枝連「可選 Skill」與「另行同意排程」。採簡化線框，不仿製不存在的實際 UI 截圖。標示「工作流程示意，非實際畫面」。

**圖示含義：**Skill 是可重用工作方法；時鐘是已同意的排程；一位助理符號足夠，不畫強制四人團隊。

**禁止添加：**不要畫預設自動建立 Skill、未確認直接執行、已接通 Oracle／SMTP、完整 Hermes 或已正式上線。

**講者補充（不上圖，90 秒）：**QA agent 提供對話、計畫、有限工具與成果的共同入口。一次工作不必先做 Skill；只有值得重複使用的方法才保存。助理資訊和能力仍要先驗證，搜尋須核准，持續排程需另外同意。現有版本的實際可用性，以部署與現場驗收為準，不能只看示意圖。

## 第 7 頁：哪些事情仍由人決定？

**目的：**建立合理期待，讓責任清楚而非製造恐懼。

**固定上圖文字：**

- 標題：哪些事情仍由人決定？
- 目標：這件工作要解決什麼問題？
- 權限：允許哪些資料、工具與持續工作？
- 採用：重要結論與來源是否值得相信？
- 停止：資料不足、錯誤或超出範圍時，交回人處理。

**構圖提示：**中央為人，周圍四張卡片。目標與採用用深藍，權限用青綠，資料不足用琥珀；只有「錯誤」的小警示符號用紅色。不要整頁大紅。

**圖示含義：**目標、鎖、核對清單、停止線分別表示四個決策點。鎖不代表任何安全認證。

**禁止添加：**不寫零幻覺、百分之百安全或多位助理必然正確；不捏造法律條款。

**講者補充（不上圖，70 秒）：**計畫與覆核可以幫助發現問題，但模型仍可能一起犯錯。來源、數字與重要判斷要由人核對。最好的流程會說明不知道什麼、卡在哪裡，而不是為了交付一份完整報告補出不存在的資訊。

## 第 8 頁：從一件值得做的工作開始

**目的：**邀請同事提出可試行的工作，不把願景當成已實現績效。

**固定上圖文字：**

- 標題：從一件值得做的工作開始
- 選題：常重複、花時間、結果能核對。
- 試跑：先小範圍，由人確認成果。
- 評估：記錄花費時間、修改量與是否有幫助。
- 邀請：你最希望少做哪一件反覆整理的工作？

**構圖提示：**左側是一張可填寫的工作卡，右側三步階梯「選題 → 試跑 → 評估」，底部突出邀請句。不要畫向上成長的績效圖，因為尚無測量資料。

**圖示含義：**循環箭頭代表重複工作；小範圍框代表試行；尺代表實際量測，不代表已有成效。

**禁止添加：**不新增節省工時數字、成功率、投資報酬或確定上線日期。

**講者補充（不上圖，40 秒）：**先挑一件小而明確的工作，保留原本人工結果作比較。看它是否減少重複整理，以及核對和修正是否反而更花時間。有效再擴大，先讓同事完成一件事，而不是先堆功能。

## 產圖後驗收清單

請產圖 agent 逐頁自查，並列出無法確認的項目：

1. 八頁尺寸、配色、字體、頁碼一致；圖片實際可開啟。不得只有文字提示而宣稱圖片完成。
2. 繁體中文字可讀，沒有錯字、亂碼、裁切或過小文字。講者補充沒有塞進圖內。
3. 流程箭頭、分支、人工確認與停止點正確；每頁最多四組主要說明。
4. 虛構材料保持一致；表單完成、說明待確認、期限未知，不擅自新增事實。
5. 第 6 頁保留候選版與排程運作限制；不暗示未完成的寄信、資料庫或完整 Hermes 已可用。
6. 沒有捏造數字、來源、公司標誌或政策。來源查核與畫面檢查分開記錄。
7. 交付圖片後，再由報告者投影檢查及排練；600 秒只是內容配置，不是已驗證的實際講述時間。
