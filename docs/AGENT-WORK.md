# rc4 日常工作入口

直接在主對話說需求；不必先切模式。辨識與規劃均無工具，一次聊天回覆包含version1建議，只有工作需求才呼叫規劃。條件完整自動本機預覽，一次確認仍固定可見範圍，排程另同意。Skill從輸入框選用；手動交辦／多助理在更多工具。能力啟用在設定先核准選用搜尋，再一次最多8次測聊天／辨識、工作格式及自主決策；搜尋另測。

目前版本1.0.0rc5、DialogueStore5；下方自主執行規則仍適用，舊「交辦工作」按鈕路徑改為直接對話或更多工具的手動入口。


# 工作代理：自主決策、Plan 與成果

版本 **1.0.0rc3 候選版**。沿用 Python3.10.4、QA agent／LangGraph；主Store schema8、DialogueStore4、69個鎖定wheels均不變。沒有引入Hermes核心、新套件或任意命令工具。完整功能缺口見[相容性清單](HERMES-COMPATIBILITY.md)，實測結果見[驗證紀錄](VALIDATION.md)。

## 最短操作路徑

1. 設定endpoint、Assistant ID、API key，明確啟動兩輪聊天測試。
2. 「工作格式」測試規劃、整理及缺資料判斷；「自主處理能力」另以最多三次停用工具的合成請求檢查決策、資料引用與補問。搜尋需人工核准工具，再明確啟動單次搜尋收據測試。每項都可能耗用API額度，不在背景執行。
3. 在主對話選「交辦工作」，預設「自主處理」。說明目標並選主助理，Skill、記憶與其他已驗證文字助理皆為選用；不自動選入資料。沒有自主能力時可明確切到「依計畫執行」，不偷偷降級。
4. 補齊問題，修改建議Plan。預覽固定目標、期間／來源要求、可用助理、工具、會傳送的資料及上限。一次「確認執行」批准這個範圍；自主模式可調整順序及搜尋關鍵字，不是保證逐項照原建議執行。
5. 同頁查看每次決策的簡短依據、實際動作、結果及額度。可取消；未知送出只檢查原請求，不暗中重送。
6. 成功成果可複製或另存可編輯Skill草稿；核對日期、來源及內容後，另行同意每日／每週台北時間排程。App需開啟或留在系統匣，CLI不運作排程器。

無金鑰可選「離線示範」；示範決策為固定合成展示，不是模型能力證據，也不能啟用真實排程。真實連線失敗不切換示範。

## 代理如何決定下一步

**決策 → 程式驗證 → 執行一個動作 → 保存結果 → 再決策。** 使用達哥既有文字／Assistants接口取得JSON建議，不依賴尚未確認的本機function calling。搜尋仍由核准的平台工具執行。

| 動作 | 允許內容 |
|---|---|
| 搜尋 | 主助理使用已核准搜尋工具，可在固定目標／期間／來源範圍內改查詢角度及關鍵字 |
| 分工 | 只選本次批准的其他文字助理，傳送指定的本次前置成果；每次一位、依序執行 |
| 彙整 | 主助理引用本次所有已取得內容產生最終成果，不略過來源或衝突 |
| 補問 | 停止並保留成果，要求補條件或重新授權；補問不派發工具 |

資料中的指令不構成授權。程式嚴格檢查動作類型、綁定、來源ID與結構；自然語言是否完全符合主題、事實是否正確，不能宣稱由程式全面證明。結果須人核對，重要限制會傳給每次執行助理。沒有寄信、檔案、DB、本機shell或安裝插件能力。

搜尋工作收到文字不等於搜過：必須有完成的工具收據；完成整理前要有https來源，最終引用不能超出已取得搜尋文字中的網址。這不是已查證網址內容、日期或可信度的保證。缺證據、覆核不通過或來源不符時停止，保留未驗證文字並標示失敗。

## 上限、中斷與重新交辦

預設最多 **6個動作、12次模型請求、600秒**。決策、分工、整理及每批搜尋工具結果續答都算請求；狀態GET不算。派發前持久保留額度，恢復不重置截止時間或請求識別。動作與請求是客戶端額度，不等於平台內部模型呼叫總數或費用上限。規劃及能力測試是另外明確啟動的請求。

相同動作、指示、助理與來源內容重複時停止；不以反覆呼叫模型修格式湊成功。達到上限、資料過長、缺條件或需要新權限時保留部分成果。補充需求按「以原需求重新交辦」只準備草稿；再提交、預覽、確認，才是新工作。新工作只保留來源識別，不自動傳送舊成果、記憶或批准。未知送出不提供這個重試捷徑。

已知run／完成快取可沿原識別明確恢復；checkpoint須與成果收據一致，不能推論exactly-once。取消／到期後阻止新派發，晚到結果不能改為成功。登入到期仍可要求取消，讀取歷史需重新登入。

舊固定流程與舊排程維持原行為。自主排程固定批准的策略、範圍、助理與Skill版本，每次注入當次日期；每次都重新決策，不能保證取得相同結果。失敗沿用暫停及漏跑防重規則，不自動擴大範圍。

## 資料與共用接口

交辦仍保存於work_orders，agent.version=2為批准快照中的自主契約。動態決策、固定請求訊息、動作定義及收據在既有workflow_steps／task payload；沒有另一套工作成功狀態。自動選入記憶、背景學習或傳送其他對話均未啟用。

來源主對話刪除仍保留獨立工作。清理工作刪除動態內容與相應本機回覆快取、保留最少防重識別；來源工作刪除後新交辦標示來源已刪除。遠端資料、其他副本與備份不保證同步刪除。

主要入口為agent_jobs／autonomous／既有WorkflowService。`agent_create`新增autonomous（預設true）及prior_task_id（僅停止後明確新建的來源識別）；舊記錄缺autonomous視為false。自主limits為max_actions／max_requests／timeout_seconds；舊max_supplements不變。`agent_autonomy_probe`為明確測試，state提供authority、budget及動態steps_status。UI與CLI使用同一服務，模型JSON不能自行批准。

## CLI

`qa.bat jobs`只列出JSON；`qa.bat`進互動工作台，與桌面互斥。

```text
/agent-probe <profileID>
/agent-autonomy-probe <profileID>
/agent-search-probe <profileID>
/job <profileID> 整理今天台股、美股及重大總經新聞
/job-preview
/job-run
/job-open <工作ID>
/job-reply {"text":"補充需求","answers":{}}
/job-inspect
/job-recover
/job-cancel
/job-schedule {"frequency":"weekly","weekday":0,"time_hhmm":"08:00"}
```

要搜尋及選團隊可用`/job-create` JSON明確提供search、team_ids與autonomous；預設的`/job`未選搜尋。`/job-edit`修改steps與limits後舊預覽失效。執行與排程確認只接受互動終端的人，不接受管線替人批准。需要沿舊模式請明確提供`autonomous:false`。

日常驗證：`.venv\Scripts\python.exe scripts/test_runner.py --suite targeted --tests tests.test_autonomous tests.test_agent_jobs`；UI另跑`scripts/web-smoke.py --agent-only`。核心交付只跑一次`scripts/verify.py development`。真實達哥格式、來源、AD及人工使用性另列not_tested，離線成功不能替代現場驗收。
