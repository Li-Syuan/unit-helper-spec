# 工作代理：交辦、Plan、有限補查與成果

版本 **1.0.0rc2 候選版**。沿用現有 QA agent／LangGraph，未加入 Hermes 程式或執行期套件。主 Store schema8、DialogueStore schema4、69個鎖定 wheels 均不變。實際達哥、AD與來源品質尚需現場驗收；本機合成成功不是正式1.0核准。

使用者要求完整 Hermes 功能，並確認保持 Python3.10.4、不換核心。其餘能力保留在[功能相容性與移植清單](HERMES-COMPATIBILITY.md)；下述是本版已實作範圍，不代表全功能完成。完整回歸尚有剪貼簿讀回錯誤，詳見[驗證紀錄](VALIDATION.md)。

## 最短使用路徑

1. 設定 endpoint、Assistant ID、API key，先明確啟動兩輪聊天測試。聊天成功即可聊天。
2. 想交辦時按「測試工作格式」，最多三次非敏感合成請求，分別驗證規劃、整理、缺資料判斷；全部停工具。需要搜尋才核准工具並另按單次搜尋測試。收到文字不等於搜尋成功。
3. 主對話選「交辦工作」。說目標，選擇是否搜尋；Skill、記憶及其他助理皆為選用，預設不自動挑選。按「開始討論與規劃」會請助理提出建議，不執行工作。
4. 必要問題每輪最多三題，可用文字／是非／單選／多選回答。條件齊全後顯示一至六步。可修改指示、順序、依賴及限制。
5. 預覽核對目標、目的助理、資料與工具名稱。一次「確認執行」批准目前修訂。改動、取消、過期或助理版本失效須重看。
6. 同頁看真實狀態、完整成果、來源及部分結果。可複製，或「存為 Skill」先產生本機可編輯草稿再確認保存；不會自動執行新 Skill。
7. 核對日期、來源與內容後，另行同意持續傳送，才設定每日／每週台北時間。App須開啟或在系統匣；CLI不運作排程器。

無金鑰可選離線示範走完 Plan 與合成成果，示範不能建立真實排程。不會自行取得新聞或冒充真實分析。

## 你批准的自動化範圍

一般工作可做搜尋、指定文字分析、覆核和整理。主助理須通過工作格式測試；額外助理只能使用已驗證且手動選入的角色。單助理不同階段各有獨立上下文，不宣稱等於獨立多代理覆核。

每份批准計畫固定方法、條件、明確選取的記憶、助理修訂及限制。預設最多 **2次補查、12次模型請求、600秒整份執行時間**；可降低或關閉補查。每個執行步驟與成果判斷占一次請求；搜尋結果交回模型續答的每一批也占一次，派發前先保留額度。狀態GET不占模型額度。計畫本身的討論、能力測試是另行明確發起的請求，不算這次執行的12次。這是客戶端派發上限，無法計量服務內部隱藏調用或保證費用。

步驟最後必須整理成果。整理前主助理以工具停用的 JSON 判斷：

| 判斷 | 行為 |
|---|---|
| `complete` | 將核准來源與已取得的補查結果交最終整理 |
| `supplement` | 只能指定原計畫的搜尋步驟ID，重查原指示、原目標與來源範圍；不能提供新指示、工具或端點 |
| `needs_input` | 停止並保留原因及部分成果，請人核對後建立修訂需求的新交辦 |

補查是重查原搜尋條件，並非自由探索瀏覽器。網站及資料文字不是授權。格式不符、資料衝突、超限、取消或權限失效都不標成功。`complete`僅表示可以整理，不保證所有事實正確。重複檢視成果／保存 Skill／讀記憶均不暗中呼叫模型。

沒有任意 shell、程式執行、資料庫查詢、文件讀寫、寄信、安裝插件或不限時Goal。SMTP仍是[接手文件](../TO-AGENT.md)中的後續提案。

## 中斷、資料與清理

請求額度在派發前寫入原task，總期限不因恢復重設。各步驟有固定ID及成果收據；LangGraph checkpoint需與收據一致。已知run或已完成快取才能沿原ID恢復，未知POST不另送。失敗不提供隱藏「新工作重試」；若需修改，明確新建並重新批准。

新交辦使用既有 `work_orders` 中版本化JSON（`kind=agent-v1`），連到原WorkflowService。執行與排程狀態只讀原task／schedule；沒有第二個runner或排程器。刪除來源主對話不連帶刪獨立交辦，來源顯示失效。透過「管理本機資料」刪除流程時也移除其交辦與規劃內容；已完成task另行刪除，保留最少防重識別。別直接刪使用中的SQLite。

明確選入的記憶及Skill可能含私人資訊；會傳給計畫列出的助理。正文中的私密資料不自動去識別。刪除本機副本不代表撤回服務端、其他副本或備份。

## CLI與開發接線

`qa.bat jobs`輸出JSON清單，不呼叫模型。`qa.bat`進互動工作台；與桌面互斥。

```text
/job demo 將指定文字整理為工作報告
/job-preview
/job-run
/jobs
/job-open 工作ID
/job-reply {"text":"補充說明","answers":{"market":["台股"]}}
/job-edit {"steps":[...],"limits":{"max_supplements":1,"max_requests":10,"timeout_seconds":300}}
/job-inspect
/job-recover
/job-schedule {"frequency":"weekly","weekday":0,"time_hhmm":"08:00"}
/job-skill
```

範例ID及省略號要替換成目前工作內容；單純示範無法排程。`/job-create`接受與UI相同的選用Skill／記憶／限制JSON。執行與排程確認僅互動終端的人可批准，不能透過管線或模型文字替人確認。`/agent-probe ID`與`/agent-search-probe ID`會先顯示請求數並確認。

主要修改入口：`agent_jobs.py`（交辦／規劃／證據）、`agent_execution.py`（有界控制節點與預算）、`workflows.py`（唯一業務狀態）、`graph_runner.py`（既有持久LangGraph）、`web_assets/agent-jobs.js`（畫面）。工具授權與Assistants帳本仍由原adapter處理。Tk維持舊功能備用，新交辦及其排程請使用WebView。

日常驗證：`.venv\Scripts\python.exe scripts/test_runner.py --suite targeted --tests tests.test_agent_jobs`；UI改動另跑 `scripts/web-smoke.py --agent-only`。核心整合交付只跑一次 `scripts/verify.py development`。真實模型測試須由使用者明確啟動，結果分開記錄。
